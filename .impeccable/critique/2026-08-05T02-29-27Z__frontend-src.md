## Design Specificity Verdict

**LLM assessment:** The product is meaningfully authored in its data model and terminology, especially on Today and in the recommendation logic. Visually, however, it still reads as a generalized iOS-inspired card dashboard: pale background, rounded white cards, cyan accent, generic metrics, and a bottom navigation shell could belong to many personal admin tools. The strongest missed opportunity is to make the strategy surface feel like a confident mine-operations decision board rather than a collection of calculators.

**Deterministic scan:** One warning was found: `layout-transition` at `frontend/src/styles.css:571`, where `transition: width 0.3s ease` can trigger layout thrash. No other detector findings were returned. No false positives identified from the available source evidence.

## Overall Impression

The app has a credible MineOps foundation and unusually careful data honesty, but the interface asks the user to navigate implementation complexity before receiving a clear strategic answer. The single biggest opportunity is to turn Strategy into a ranked decision workflow with supporting tools progressively revealed underneath.

## What's Working

- **Today has a useful product promise:** “Best Next Move” translates roster data into an actionable recommendation instead of opening on CRUD.
- **Data provenance is a differentiator:** test-fixture, limited-data, offline, catalog-release, and recovery states show a strong refusal to present guesses as facts.
- **More uses progressive disclosure:** collapsible settings/operations sections are a good pattern for a personal tool with advanced sync and import controls.

## Priority Issues

### [P1] Strategy is a toolbox before it is a decision

**Why it matters:** The Strategy page contains Frontier, lineup, upgrades, tier list, progress, Stella, and crystal planning, plus many manual inputs. A player asking “what should I do next?” must choose among several mental models before seeing the recommendation.

**Fix:** Lead with one ranked “Recommended next actions” queue. Show the top recommendation, expected reason, confidence/data limitations, and a single primary action. Move calculators and comparison tools into secondary sections or a “Tools” disclosure. Keep the current plan menu as an expert shortcut.

**Suggested command:** `$impeccable distill frontend/src/pages/StrategyPage.tsx`

### [P1] Today’s fallback states expose roadmap copy instead of user value

**Why it matters:** “Full mine-state analysis is the next dashboard milestone” tells the user what the team has not built. It consumes prime space while weakening trust in the current product.

**Fix:** Replace roadmap language with the best currently supported evidence: strongest upgrade opportunity, weakest covered area, stale-data warning, or a concise explanation of why no recommendation can be made. Keep future work in project documentation, not the product surface.

**Suggested command:** `$impeccable clarify frontend/src/pages/TodayPage.tsx`

### [P2] Critical freshness and confidence signals are too dispersed

**Why it matters:** Sync status is computed, but the header status is hidden by default and catalog source/release details live in More or inside strategy cards. Users can miss whether a recommendation is current, cached, fixture-backed, or limited by missing data.

**Fix:** Add one compact, always-visible data-confidence line near the page title: source, freshness, and confidence/limitations. Make it expandable for release and manifest details. Use plain language first; reserve technical IDs for the detail view.

**Suggested command:** `$impeccable polish frontend/src/App.tsx frontend/src/pages/StrategyPage.tsx`

### [P2] The visual system is coherent but too generic and inconsistently authored

**Why it matters:** The cyan/white rounded-card language is serviceable, but Strategy’s extensive inline styles create inconsistent spacing, borders, button states, and hierarchy. The detector also flags a width animation at `styles.css:571`.

**Fix:** Extract strategy primitives for plan navigation, recommendation cards, confidence badges, field groups, and secondary actions. Replace `transition: width` with a transform/opacity or grid-based approach where possible, and add explicit `:focus-visible` styling to the shared controls.

**Suggested command:** `$impeccable document frontend/src/styles.css`

### [P2] More reads like an operations console

**Why it matters:** Authentication, Kolibri credentials, catalog recovery, capture bridge controls, imports, and snapshots are all valid capabilities, but the grouping reflects implementation ownership more than the user’s tasks.

**Fix:** Organize around “Keep my data current,” “Account and devices,” and “Recovery and history.” Put the common Sync Now/import action first, technical diagnostics behind an advanced disclosure, and explain consequences before destructive or recovery actions.

**Suggested command:** `$impeccable layout frontend/src/pages/MorePage.tsx`

## Persona Red Flags

**Alex — Power User:** The filters and saved plans help, but Strategy requires switching among seven plan types and manually entering event values before the core recommendation is visible. There is no evident keyboard shortcut or quick-jump pattern for repeated strategy review.

**Jordan — First-Timer:** “Verified catalog unavailable,” “manifest,” “bootstrap fallback,” and “limited data” are accurate but technical. A first-time user who has not imported data is told to open More without a clear two-step setup path or explanation of what data is needed.

**Riley — Data-Recovery User:** The app preserves cached data and provenance, which is good, but recovery controls are distributed across More and import history. It is not immediately obvious whether refreshing a catalog changes player data, whether an import is reversible, or which source is currently authoritative.

## Minor Observations

- The header sync action uses an icon plus hidden text on narrow screens; the visible icon needs an especially strong state treatment because it carries a core action.
- Inline `style={{...}}` blocks in Strategy make responsive and theme adjustments harder to reason about.
- Technical release IDs are useful for support/debugging but should be visually subordinate to player-facing labels.
- Empty states are generally honest; add a specific next action and a short explanation of the missing prerequisite.
- The current CSS uses broad `transition: all` rules in several shared controls; narrow transitions improve predictability and accessibility.

## Questions to Consider

- Should Strategy open directly on the single best next action, with the current seven tools treated as supporting modes?
- Is the intended emotional tone calm and analytical, or should the mine/progression metaphor be more visible in the visual language?
- Which matters more for the next pass: reducing Strategy choice overload, or making data freshness/confidence impossible to miss?
